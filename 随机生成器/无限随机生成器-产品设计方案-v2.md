# 「下一件」无限随机生成器 · 收敛版产品设计 v2

> 目标：一个可直接部署到互联网、无需后端与登录的静态网页。核心是"随机一下"按钮，内容以科普/知识为主（约 45%），内容库从数千条扩展到数万条，且所有机制只服务一个目标——让用户每点一次，都对下一次产生期待。
>
> 版本 v2.0 · 2026-08-12 · 本文档不含代码

---

## 0. 设计总纲

**唯一目标**：让用户每点一次"随机一下"，都对下一次会出现什么产生一点期待。

**三条铁律**：

1. 内容即产品。数量靠"原子库 + 组合变体"的架构解决，质量靠"原子审核 + 来源标注"解决，两者缺一不可。
2. 随机必须有记忆。纯随机会快速疲劳；真正的随机感来自"有约束的随机"——去重、冷却、情绪起伏、稀有峰值。
3. 功能只服务目标。任何不增加"期待感"的功能都砍掉或推迟，绝不堆砌。

## 1. 最终产品定位

### 一句话定位

一个打开的瞬间就只剩一个按钮的网页：**"今天，你会遇见什么？"→ 随机一下 → 一件值得看的内容 → 再来一个。**

### 体验目标（三个用户心理，按顺序发生）

1. "我也不知道下一次会蹦出来什么。"（悬念）
2. "这个东西我居然不知道。"（价值）
3. "再点一下，说不定下一个更有意思。"（复购）

### 明确"不是"

- 不是知识管理工具、不是学习软件、不是办公工具。
- 不是抽卡游戏（稀有度只是味道，不是收集压力）。
- 不是 AI 对话（运行时绝不实时调用 AI）。
- 不是资讯流（没有刷新式信息轰炸，只有单件内容）。

### 成功指标（第一版可观测）

- 单次会话点击数（目标：中位数 15-30）
- 平均会话时长
- "再来一个"的连续点击率
- 收藏率（每 20 次点击至少 1 次收藏）
- 分享卡使用率
- "内容有误"反馈率（越低越好，同时证明可信度）

## 2. 最推荐的整体架构

### 2.1 三层架构：离线优先

```
内容原子层（Fact Atoms）     已验证的事实/素材，一份事实只存在一次
        ↓ 生成呈现变体（不改变事实）
内容条目层（Content Items）  用户实际看到的内容（teaser/why/deep + 元数据）
        ↓ 打包与索引
运行层（Runtime）            静态网站 + 调度器 + 本地状态（浏览器内）
```

关键点：**事实只存一份（原子），呈现可以有很多份（变体）**。这同时解决"数量不够"和"质量不可控"两个问题——审核一个原子，它派生的所有变体都继承可信度。

### 2.2 数据流

**内容管线（离线，构建期）**

选题 → 写成原子 → 生成呈现变体 → 事实核查 → 相似度检查 → 审核发布 → 打包为数据文件 + 索引清单。

**运行时（在线，纯前端）**

拉取清单 → 按需懒加载数据文件 → 调度器选内容 → 分层渲染 → 用户行为写回本地 → 更新状态（去重环、统计、旅程）。

### 2.3 为什么这个架构能到"数万条"

- 2,000 个已验证原子 × 平均 5-6 个呈现变体 ≈ 1 万-1.2 万条目。
- 故事、句子、选择、任务等不易模板化的内容人工直写 3,000-5,000 条。
- AI 只负责"生成候选"，经人工审核后入库 5,000-15,000 条。
- 合计可达 2 万-3 万条，加上系列与关系复用，长期可稳定在数万。
- 防重复感知：同一原子最多 6 个变体，并按语气/难度/长度错开分布；构建期用相似度检测拦截"换汤不换药"的变体。

## 4. 内容数据库结构

### 4.1 双层模型

**原子表（fact_atoms）**：一份已验证事实只存在一次。

| 字段 | 说明 |
|---|---|
| atom_id | 稳定 ID，如 ATOM-0001 |
| domain | 所属领域 |
| statement | 事实陈述（唯一事实源） |
| subject / tags | 主题对象、标签 |
| factual_type | 事实类型（见 4.6） |
| confidence | 置信度：verified / widely_accepted / disputed / legend / anecdote |
| source | 来源 + 链接 |
| last_verified | 最近核验日期 |
| status | draft / review / published / deprecated |
| variants_count | 已派生变体数（用于控制上限） |

**内容条目表（content_items）**：用户实际看到的东西。

| 字段 | 说明 |
|---|---|
| id | 稳定 ID，如 ANM-0001（类别前缀 + 序号） |
| slug | 语义化短名 |
| category / subcategory / topic | 一级/二级分类、主题 |
| tags / keywords | 标签、关键词 |
| factual_type | FACT / HISTORY / SCIENCE / OPINION / THOUGHT_EXPERIMENT / FICTION / LEGEND / HUMOR |
| presentation | 呈现型：Q_A / DIDYOUKNOW / MYTHBUST / STATEMENT / MINI_QUIZ / COMPARE / ONE_LINER / STORY / LETTER / ARCHIVE / CHOICE / TASK / GAME |
| rarity | COMMON / UNCOMMON / RARE / VERY_RARE / SECRET / MYTHIC |
| difficulty | 1-5 |
| length | short / medium / long |
| tone | curious / funny / solemn / weird / warm / dark / whimsical |
| layers | teaser / why / deep 三层内容（分层展示） |
| explanation | 备用解释字段 |
| source | 来源（name + url + confidence） |
| related | 相关条目列表（id + 关系类型） |
| series | 所属系列（如 future_letters）与序号 |
| weight | 基础权重（默认 1.0） |
| quality_score | 质量分（1-5，审核时打） |
| origin | human / template / ai_candidate |
| atom_id | 引用的原子 ID（模板生成条目必填） |
| status | draft / review / published / deprecated |
| version / created_at / updated_at | 版本与时间戳 |

### 4.3 关系索引（related）

关系带类型，供探索链使用：

- DEEPER：同一主题更深一层
- BECAUSE：解释为什么
- WHAT_IF：反事实 / 假设延伸
- SIMILAR：类比 / 相似现象
- WOW：更震撼的后续

### 4.4 factual_type 八类及展示规则

| 类型 | 含义 | 界面展示 |
|---|---|---|
| FACT | 真实事实 | 标"真实" |
| HISTORY | 真实历史 | 标"历史" |
| SCIENCE | 科学知识 | 标"科学" |
| OPINION | 观点 | 标"观点" |
| THOUGHT_EXPERIMENT | 思想实验 | 标"思想实验" |
| FICTION | 虚构 | 标"虚构" |
| LEGEND | 传说 | 标"传说" |
| HUMOR | 纯娱乐 | 标"娱乐" |

规则：**用户永远不需要猜这是真是假**。类型标注在内容卡片角落，极小但清晰。

## 5. 内容数量规划与扩展路径

| 阶段 | 目标量 | 构成方式 | 验收标准 |
|---|---|---|---|
| 第一阶段（上线） | 600-800 条 | 人工精选直写，覆盖全部 25 类，核心科普类更多 | 前 200 次点击几乎不重复；无事实错误 |
| 第二阶段 | 3,000-5,000 条 | 1,000+ 原子 × 变体 + 人工新增直写 | 同一原子变体不感知重复；每类 ≥ 100 条 |
| 第三阶段 | 10,000 条+ | AI 生成候选（原子+变体）→ 人工审核 → 入库 | 审核流水线跑通；每周入库 ≥ 200 条 |
| 长期 | 数万条 | 原子复用 + 系列内容 + UGC（审核制，可选） | 构建期检查全绿；运行时性能不降 |

扩展原则：

- 新增内容 = 新原子 + 新变体 + 新关系，三件事一起做。
- 每个原子变体上限 6 个，且语气/难度/长度必须错开。
- 每批入库前跑自动化检查（Schema 校验、相似度去重、来源完整性、禁词表）。

## 6. 随机算法与防重复算法

### 6.1 调度器总流程（每次点击）

1. 读状态：去重环、会话与今日已见、类别/情绪计数器、偏好增量、旅程进度、渴望值。
2. 定基调：根据最近 5 条内容的情绪/长度，选择下一个"基调桶"（好奇 / 轻松 / 沉思 / 荒诞 / 微恐 / 温暖），保证情绪起伏。
3. 抽类别：在基调桶内按"基础权重 × 供给量 × 冷却惩罚 × 用户偏好"加权抽取。
4. 抽条目：在类别内过滤（未见过、今日未见、稀有度权重、与上一件呈现型不同），加权抽取。
5. 过检查：类别冷却、主题冷却、长短交替、情绪交替、类型交替，违规则重抽（最多 3 次）后强制兜底。
6. 插事件：组合卡、旅程内容、稀有事件按概率注入。
7. 写状态：更新去重环、计数器、统计、渴望值。

### 6.2 权重模型

- 基础权重：25 大类的目标比例。
- 供给量系数：某类未看过条数越少，权重越低，防止"同一类反复出旧货"。
- 冷却惩罚：最近出现 1/2/3 次 → ×0.4 / ×0.15 / ×0.05。
- 主题惩罚：与最近 2 条标签重叠 > 40% 时 ×0.3。
- 用户偏好：收藏过的类 +20%，不感兴趣的类 -30%，封顶，绝不做"猜你喜欢"。
- 稀有度权重：COMMON ×1 / UNCOMMON ×0.5 / RARE ×0.15 / VERY_RARE ×0.04 / SECRET ×0.01 / MYTHIC ×0.002。

### 6.3 防重复六层

| 层 | 规则 |
|---|---|
| ID 去重环 | 最近 min(200, 池子 5%) 条不重复 |
| 类别冷却 | 同类别至少间隔 2 次；连续 3 次同类直接禁止 |
| 主题冷却 | 标签重叠过高时降权（见 6.2） |
| 长短交替 | 不出现连续 3 条长内容 |
| 情绪交替 | 不出现连续 3 条同情绪 |
| 类型交替 | 不出现连续 3 条同呈现型（知识→知识→知识被禁止） |

补充：当日已见不重复（池子 ≥ 300 时生效）；会话内优先消耗"从未见过"的池子；长内容占比按权重控制在 15% 以内。

### 6.4 冷启动与渐入

- 前 5 次点击：偏向"秒杀型"（动物/宇宙/人体/历史冷知识、奇怪真实事件），让人立刻"卧槽"。
- 第 6-20 次：混入心理、哲学、故事、选择。
- 20 次以后：全类别混池。权重随点击次数线性过渡。

### 6.5 概率总表（概念值，可调）

| 项 | 概率 |
|---|---|
| 普通内容 | 约 85% |
| 组合卡（本次会话内容串联） | 约 5% |
| 旅程/系列内容注入 | 约 3% |
| 稀有事件（事件级） | 约 3-5%（渴望值加成，封顶 8%） |
| "硬随机"终极时刻 | 0.01%（不受任何加成） |

### 6.6 稀有度出现率（内容级）

COMMON 约 70% / UNCOMMON 约 22% / RARE 约 6% / VERY_RARE 约 1.8% / SECRET 约 0.18% / MYTHIC 约 0.02%。

## 7. 内容关系与探索链

### 7.1 垂直探索：深度层级

每条内容最多四层，渐进展开：

1. teaser：一句话钩子（≤ 40 字）
2. why：展开一点（≤ 120 字）
3. deep：再深入一点（≤ 300 字）
4. related：相关内容（2-3 条链接）

用户点"深入了解"逐层展开；这本身就是"内容 → 好奇 → 深入 → 另一个内容"的探索链。

### 7.2 横向探索：关系类型

相关内容带关系类型（DEEPER / BECAUSE / WHAT_IF / SIMILAR / WOW），例如：

章鱼有三颗心脏（teaser）→ BECAUSE 章鱼循环系统为何特殊 → WOW 深海动物为何普遍奇怪 → SIMILAR 血液颜色不同的生物。

### 7.3 链模式

- 用户点"相关内容"进入链模式：下一件是上一件的 related，界面显示"探索链 3/7"，可随时退出回到随机。
- 系统偶尔（约 8%）自动注入"温柔关联"：下一件内容与上一件有隐秘关系，让用户产生"这是不是故意的"。

### 7.4 系列内容

- 预置系列："未来来信"（8 封）、"████ 机构机密档案"（6 份）、"梦境日记"（5 段）。
- 系列入口低概率触发；进入后按间隔 1-5 次点击自然出现下一件；进度本地保存。
- 完成一个系列：给一块世界观碎片 + 一个成就。

### 7.5 关系来源

- 编辑手工关联（最可靠，第一版全部手工）。
- 构建期按标签相似度自动推荐候选（标记为 suggested），人工确认后转正。

## 8. 稀有事件系统

### 8.1 设计原则

- 不跳吓、不弹窗、无刺耳音效、无全屏闪烁。
- 稀有事件必须有内容价值，不能只是特效。
- 目标是"这到底是随机的，还是它故意的？"，而不是"吓我一跳"。
- 不是抽卡：没有抽卡券、没有保底、不强迫集齐；成就不需要 MYTHIC 也能全收集。

### 8.2 事件清单（事件级，按稀有度）

| 层 | 事件 | 表现 | 概率 |
|---|---|---|---|
| 微稀有 | 温柔巧合 | 本次内容与上一张隐秘关联，角落小字"你们不是偶然相遇" | 3% |
| 微稀有 | 回应式内容 | 出现"看起来知道你喜欢什么"的内容（引用你本地收藏过的主题） | 2% |
| 稀有 | 风格切换 | 整页临时切到"终端风"或"纸页风"，可手动恢复 | 1% |
| 稀有 | 隐藏问题 | 角落出现几乎看不见的小字问题，点它进入隐藏内容 | 0.8% |
| 稀有 | 世界观碎片 | 出现"████ 机构机密档案 No.xxx"，可收集 | 0.8% |
| 稀有 | 打破第四面墙 | 温和引用你的数据："这是你第 37 次点击。你还没收藏过任何东西——是不是都不够好？" | 0.5% |
| 极稀有 | 隐藏故事入口 | 开启一条独立隐藏故事链 | 0.2% |
| 终极 | 唯一时刻 | "你刚刚看到了 99.99% 的人看不到的东西。祝你今天发生一件小事。" | 0.01%（纯硬随机） |

### 8.3 渴望值

- 点击 +2；收藏 +5；"不感兴趣" +1；连续 5 次无收藏 +2。
- 稀有触发概率 = min(8%, 渴望值 × 0.12%)；触发后清零。
- 0.01% 硬随机通道不依赖渴望值，保证"纯粹运气"的惊喜。

### 8.4 打破第四面墙的尺度

- 只使用本地可见数据（点击次数、收藏数、日期），绝不假装知道身份/位置/隐私。
- 文案方向：好奇、温柔、带点自嘲。

## 9. 长期可玩性

设计原则：**每天都有回来的理由，但没有被绑架的感觉**。

### 9.1 核心三件套（第一版必须）

- 浏览历史：时间线可回看，本地保存（IndexedDB，上限约 5,000 条后裁剪）。
- 收藏与标签：收藏带类别标签，可自定义。
- 内容统计：已探索类别数、总点击、遇见的稀有数、连续探索天数。

### 9.2 每日节奏

- 今日发现：日期种子，每天一个主题（如"今天的内容都和水有关"），今日内容 30% 贴合主题。
- 连续探索：温和 streak（7/30/100 天成就），不惩罚断签、没有红点。

### 9.3 里程碑

- 隐藏成就：里程碑 + 行为型（"第 100 次点击""集齐 5 封未来来信""触发 3 次稀有"）。
- 探索人格：每 30 次点击生成一次报告（如"深夜型荒诞主义者"），可分享——它是反思时刻，不是排行榜。

### 9.4 内容持续供给

- 每周更新数据包（纯 JSON，增量加载），让"没看过"的池子永远存在。
- 内容版本化：旧条目可被修订，修订自动同步到引用它的变体（通过原子）。

### 9.5 反焦虑红线

- 无签到惩罚、无每日任务奖励、无排行榜、无红点、无"集齐"压力。
- 今日发现错过不补，但也不提醒。

## 10. UI / UX 完整方案

### 10.1 信息架构：首页就是全部

首屏只有一个标题、一个按钮、一行小字。所有"档案"功能收进一个抽屉，不占主界面。

```
┌──────────────────────────┐
│  【下一件】        ☰ 档案  │
│                          │
│   今天，你会遇见什么？     │
│      [ 随机一下 ]        │
│  一个好奇心盲盒 · 全部本地 │
└──────────────────────────┘
```

点击后：

```
┌──────────────────────────┐
│ 动物·冷知识   ✦稀有(如有)  │
│                          │
│  章鱼有三颗心脏。         │
│    ▾ 展开一点             │
│    ▾ 再深入一点           │
│  相关 ▤ ▤  来源 [科学·可靠]│
│  ♥收藏  ✕不感兴趣         │
│      [ 再来一个 → ]      │
└──────────────────────────┘
```

### 10.2 主流程

标题页 → 点击"随机一下"（按钮下沉 + 微光，400-600ms 内容浮现）→ 阅读 → 三个动作（♥ / ✕ / 深入了解）→ "再来一个 →"（按钮位置固定，减少寻找成本）。键盘：空格/→ 下一件。

### 10.3 内容卡片设计

- 类别标签：左上角极小（如"历史 · 真实"），一眼给可信度。
- 稀有标记：RARE 以上显示 ✦，VERY_RARE 以上显示金色 ✦，不做弹窗。
- 主体：teaser 大字 → 展开后 why → deep。
- 来源：底部一行极小字，默认收起，可点开（"来源：xxx"），不做成论文。
- 动作：♥ 收藏、✕ 不感兴趣、深入了解、相关内容。
- "内容有误"反馈：藏在来源行旁边，极小，点了进入反馈（本地记录 + 提示已提交）。

### 10.4 视觉方向（4 个）

**方向 1｜深夜档案馆（主推）**

- 近黑底色（墨蓝黑）+ 单一琥珀色强调 + 衬线大标题 + 等宽字体做元数据。
- 内容像"档案条目"，稀有内容像"红色机密文件"，风格切换可临时变成"终端"。
- 配"晨间阅览室"浅色皮肤（暖纸色），同一布局，解决长时间阅读疲劳。

**方向 2｜宇宙观测站**

- 深空蓝黑渐变 + 极淡星点；内容出现在"捕获信号"窗口中，类别像星座。
- 优雅、氛围感强；风险是主题感过重，适合作为皮肤而不是默认。

**方向 3｜标本陈列馆**

- 中性深灰绿墙面 + 细边框"标本牌"；元数据用博物馆标签式小号大写字母。
- 最接近"数字博物馆"，高级感强；适合做科学类内容的容器。

**方向 4｜游戏终端（彩蛋皮肤）**

- 等宽字体 + 磷光绿 + 打字机效果；只在稀有事件/世界观碎片时短暂出现，作为"进入机密层"的仪式。

推荐组合：默认"深夜档案馆" + 浅色"晨间阅览室"切换 + 稀有事件临时切"终端"。三种皮肤共享同一套内容布局，皮肤只改配色与字体细节，不做三套界面。

### 10.5 动效与声音

- 内容出现：淡入 + 轻微展开，400-600ms；哲学/沉思类更慢。
- 声音：默认静音；可开"环境音"（纸张翻动 / 宇宙底噪 / 终端键盘声），按钮音效极轻。
- 无任何强制动画、无引导教程、无弹窗。

### 10.6 响应式与无障碍

- 手机单手操作：按钮够大，动作按钮在拇指区。
- 字号可调（浏览器默认即可），对比度满足 WCAG AA。
- 键盘可完整操作。

### 10.7 状态面板（抽屉）

- 档案 = 历史时间线 + 收藏 + 统计 + 成就 + 今日发现。
- 默认收起；展开后不打断阅读（右滑抽屉，半透明遮罩可点背景关闭）。

## 11. 静态网站技术方案

### 11.1 形态

- 纯静态单页应用：HTML/CSS/JS，无后端、无数据库、无登录、无运行时 API Key。
- 首选原生或轻量框架（Vite + Svelte/Preact 均可），输出纯静态文件，任何静态托管可部署。

### 11.2 数据加载（数万条的解法）

- 首屏只打包"起步内容"（约 1,500-2,000 条精选，覆盖所有类别）与清单 index.json，保证离线可用、点击即时。
- 其余数据按"类别文件"懒加载：点中某类首次出现时拉取该文件，之后缓存。
- 缓存层：IndexedDB 存数据文件副本 + 访问历史；Service Worker 做 PWA 离线。
- 增量更新：index.json 带版本号，更新只拉变更文件。

### 11.3 本地状态

- localStorage：计数器、偏好增量、旅程进度、成就、设置（小数据）。
- IndexedDB：历史时间线、数据文件缓存（大数据，带裁剪策略）。

### 11.4 构建与校验管线（离线脚本，非运行时）

- Schema 校验：所有条目符合 4.2 的字段规则。
- 相似度检查：shingle / TF-IDF 相似度阈值，拦截"换汤不换药"的变体与重复导入。
- 来源检查：SCIENCE/FACT/HISTORY 类必须有 source；confidence 为 disputed 的必须标争议。
- 禁词表：伪科学关键词（作为事实出现时拦截）、医疗诊断词。
- 统计输出：每类条数、变体数、审核状态分布，生成 index.json。

### 11.5 性能预算

- 首屏 JS/CSS < 300KB（gzip 后）。
- 起步内容包 < 1MB（gzip 后）。
- 单个类别文件 200-800KB，按需加载。
- 单次点击到内容出现 < 300ms（本地索引内查询）。

### 11.6 部署

GitHub Pages / Vercel / Netlify / Cloudflare Pages 均可；纯静态输出，无环境变量。

## 14. 如何保证科普内容质量

### 14.1 来源政策（按类型）

| 类型 | 要求 |
|---|---|
| SCIENCE / FACT | 必须有来源；优先公认来源；confidence=disputed 必须标"存在争议" |
| HISTORY | 必须有来源或明确"有不同说法" |
| LEGEND / FICTION / HUMOR / OPINION / THOUGHT_EXPERIMENT | 不要求权威来源，但必须标对类型，绝不当事实 |

### 14.2 置信度分级

verified（有明确可靠来源）/ widely_accepted（学界共识）/ disputed（有争议）/ legend（传说）/ anecdote（孤例轶事）。

### 14.3 好内容门槛

每条至少命中 2 条：让人产生疑问 / 画面 / 意外 / 想继续看 / 想讨论 / 笑 / 沉默几秒 / 想到自己 / 学到真的东西 / 想"再来一个"。

### 14.4 负面清单（一票否决）

老套鸡汤、空洞哲理、伪名言、虚假历史、伪科学、为猎奇而猎奇、过度说教、医疗建议、千篇一律句式。

### 14.5 审核与更正

- 流程：draft → review → published；每周抽 10% 复评；"内容有误"反馈进待审队列。
- 原子级更正：一个事实错了，改原子，所有派生变体同步修订（version +1）。
- 下线机制："不感兴趣"率 > 40% 且样本 ≥ 30 的条目标记待审。

### 14.6 自动批量检查

- Schema 校验、来源缺失检查、相似度阈值、禁词表、字数上下限、变体数上限。
- 构建期全绿才允许发布新数据包。

## 15. 你没想到、但值得加入的机制（精选 6 个）

每个机制都直接服务于"对下一次的期待"：

1. **给未来的自己留言（时间胶囊）**：用户写一句话，7/30 天后它作为"来自过去的你"随机出现一次。这是全项目最贴合"无限 + 随机 + 个人"的机制，成本极低（纯本地），回报是"卧槽"级记忆点。
2. **随机组合时刻（Mashup）**：约 5% 概率，把本次会话里看过的两件内容串成一个新问题（"你刚看到猫的嗅觉是人的 14 倍——如果猫来替你闻，你今天会先闻到什么？"）。它让"这次会话"本身变得有叙事感。
3. **引用卡 + 直达链接**：任意内容生成一张带编号的分享卡，附带 ?c=XXXX 直达链接；朋友打开直接看到同一件内容。无账号的传播闭环，也天然为"我居然不知道"做口碑扩散。
4. **内容回声（私密彩蛋）**：极低概率，一条新内容悄悄引用你收藏过的主题（"你似乎对深海有兴趣——送你一条深海的"）。它制造"它在看我"的错觉，但只用本地数据，温柔不惊悚。
5. **"不感兴趣"反馈闭环**：偶尔（约 1%）在内容下方出现一行小字："因为你标记过，这类内容出现得少了。"让用户信任调度器，也防止用户以为随机是坏的。
6. **"内容有误"纠错按钮**：科学类内容必须能低成本纠错。它既是质量机制，也是信任品牌——"这里的每条内容都可以被质疑"。

可选但暂缓：静默模式（隐藏所有元数据）、探索足迹星图（每 50 次点击画一张类别轨迹）、个人专题页（同类别收藏 ≥ 3 自动成辑）。
